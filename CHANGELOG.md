## [0.8.0] - 2026-06-19

### Added

The kernel's refinement-lineage record for a skill — the entity the Skill Refiner appends to as it accepts edits. **SEPARATE from `SkillSnapshot`** (DR-028 T1, ISEDC Session 7): `SkillSnapshot` (§ 2.9) content-addressed-pins a skill's source state; `SkillVersion` captures the refinement LINEAGE. **No breaking changes — net-new entity; the one-way-door is the @core publish.** The footprint mirrors the `SkillSnapshot` entity exactly: `schemas/v1/skill-version.schema.json` (`$id: https://github.com/jeremylongshore/intent-eval-core/schemas/v1/skill-version.schema.json`, `additionalProperties: false`), the hand-authored TS interface `src/entities/SkillVersion.ts` + `SkillVersionKind`, the hand-authored Zod validator `src/validators/v1/skill-version.ts` + `_generated/skill-version.ts` codegen reference, `index.json` registration (`kind: entity`), the Python Pydantic mirror (`python/.../_generated/skill_version_schema.py` + `models.py`/`__init__.py` re-export under the canonical name `SkillVersion`), and golden fixtures + AJV/Zod parity tests (the schema-file count bumps 19 → 20, the entity count 13 → 14).
  - **Field set = the DR-028 T1 ratified shape** (lines 86–93 + P0-RATIFY-5 line 270): `id` (`Uuidv7`, the `skill_version_id` the predicate references), `skill_id` (`KebabSlug`, mirrors SkillSnapshot), `version_kind` (CLOSED enum `edit|revert|restore` — the **load-bearing signable discriminator** per DR-028 T1 line 90), `parent_version_id` (`Uuidv7`, **nullable** for a root version — references the prior SkillVersion in the lineage, NOT an FK to SkillSnapshot, DR-028 T1 line 91), `source_snapshot_hash` (`Sha256Prefixed`), `refiner_strategy_id` (CISO signed-manifest mechanism-traceability binding, P0-RATIFY-5), `created_at` (`Rfc3339`), `created_by` (`ActorIdentity`), and the reserved-additive `tenant_id?` (deferral-G, mirroring SkillSnapshot).
  - **`source_snapshot_hash` is a REFERENCE, NOT a foreign key** (DR-028 T1 line 92) — a READ-ONLY content hash of the SkillSnapshot at the moment of refinement. There is **no enforced relational integrity**; the SkillSnapshot it names need not exist in any table the kernel knows about. The CTO's "orthogonal-no-FK" fallback is folded into the discriminator path exactly here. Typed `Sha256Prefixed` identically to the `skill-refiner-pass/v1` predicate body's `source_snapshot_hash`, and `id`/`parent_version_id` typed `Uuidv7` identically to the predicate's `skill_version_id`/`parent_version_id` — so the already-shipped predicate's references align with this entity (a test asserts the valid fixtures share IDs).
  - **NO state machine + status/signing fields are DEFERRED** per the DR-028 T1 binding minority constraint (lines 105/108): "Phase C ships entity + discriminator + `parent_version_id` only ... state-machine formalism deferred ... authored as a SECOND DR in v0.4.0 — not now." So `SkillVersion` ships WITHOUT a lifecycle `TransitionMap` and WITHOUT the P0-RATIFY-2 fields (`status`, `signing_mode`, `rekor_log_index`, `pending_production`, `retry_after`, `signing_downgrade_reason`) + the `rekor_log_index iff signing_mode='production' AND status='active'` cross-field invariant. Adding them later is additive; pre-committing them into a signed shape now would be the irreversible mistake (one-way-door discipline). The minimal lineage-record shape is the safe shape to publish first.

### Changed

- **DR-085 pre-release corrective decisions (D3/D4/D5) — one-way-door fixes applied before v0.8.0** ([ISEDC corrective council, 7-0](https://github.com/jeremylongshore/intent-eval-lab/blob/main/000-docs/085-AT-DECR-isedc-kernel-onewaydoor-correction-2026-06-17.md)). These correct the still-`[Unreleased]` `SkillVersion` + `skill-refiner-pass/v1` shapes above; **where they conflict, this block governs** — notably it supersedes the `Sha256Prefixed` hash typing and the original `source_snapshot_hash`/subject-digest semantics described above.
  - **D3 — lineage integrity + parent nullability.** `SkillVersion` gains a self `content_hash` and a `parent_content_hash` (tamper-evident lineage anchor; `null` iff root). The hash alphabet for `content_hash`/`parent_content_hash`/`source_snapshot_hash` is now **bare `sha256`**, aligned byte-for-byte to `SkillSnapshot.combined_sha` (the earlier `Sha256Prefixed` typing left the entity↔snapshot join unresolvable). The `skill-refiner-pass/v1` `parent_version_id` is now **nullable**, so a root `SkillVersion` emits a valid pass without forging a parent.
  - **D4 — semantic disambiguation + label.** Added `result_snapshot_hash` (the POST-EDIT output snapshot) to the predicate; `source_snapshot_hash` now means the PRE-EDIT input consistently on both entity and predicate (it previously meant opposite things on each side). The staging `signing_mode` label is **`sigstore_staging`** (`ln` retired).
  - **D5 — three-layer enforcement of signed cross-field invariants.** `verdict==='accept' ⇒ every named_dimension_deltas[].non_regressed === true`, and `version_kind ∈ {revert,restore} ⇒ parent_version_id !== null`, are now enforced at JSON-Schema (`if/then`) + Zod (`superRefine`) + Pydantic (`model_validator`) — previously asserted in prose but enforced nowhere. Python optional-not-nullable parity fixed (`tenant_id`/`cost_record_ref`/`replay_fidelity_level`/`signing_downgrade_reason`). Negative fixtures (accept+regressed, revert/restore-on-root) wired as expected-rejections.
  - The deferred `status`/`signing_mode`/`rekor_log_index` fields (DR-028 T1 line 105 vs P0-RATIFY-2) stay deferred until the authoring signing root is provisioned (DR-082 trigger 3); recorded in DR-085 D1.

First public release. The canonical contracts kernel for the [Intent Eval Platform](https://github.com/jeremylongshore/intent-eval-lab) — TypeScript types, JSON Schemas, Zod validators, and state machines for the 13 canonical entities.

> **Adoption notes for downstream consumers.** Three sibling platform repos will migrate to this package.

| Repo | What to import | Migration shape |
| --- | --- | --- |
| `audit-harness` | `@intentsolutions/core` types for entities the harness emits predicate rows about; `@intentsolutions/core/validators/v1/gate-result-v1` for runtime parsing | Replace any local `gate-result/v1`-shaped types; brand existing identifier strings via the Zod parsers; emit signed rows whose predicate body satisfies `GateResultV1Schema` |
| `j-rig-skill-binary-eval` | `@intentsolutions/core` for `JudgeDecision`, `EvalRun`, `SessionTrace`, `ToolInvocation`; `@intentsolutions/core/validators/v1` for runtime parsing | Move existing entity types into this package; map judge verdicts (UPPERCASE `JudgeVerdict`) through the `@j-rig/rollout-gate` translator to RolloutGate decisions (lowercase `RolloutGateDecision`) |
| `intent-rollout-gate` | `@intentsolutions/core/validators/v1/gate-result-v1` for parsing DSSE-wrapped predicate bodies | Replace local schema definitions with the canonical `GateResultV1Schema`; verify DSSE signatures externally (out of kernel scope); apply consumer-side policy from `tests/TESTING.md` per § 7.6 architectural separation |

> **Codegen tooling:** the consuming codemod work was scoped down to "hand-migration acceptable" per iec-E09 acceptance criteria (sub-children E09b/c/d demoted to P2). No automated codemod ships in v0.1.0; the migration shape above is the documented manual recipe.

### Added

- **`@intentsolutions/core`** (main entry) — pure types only, zero runtime dependencies.
  - 13 canonical entity interfaces per [Blueprint B § 2](https://github.com/jeremylongshore/intent-eval-lab/blob/main/000-docs/012-AT-ARCH-platform-runtime-blueprint.md): `EvalSpec`, `EvalRun`, `MatcherMap`, `EvidenceBundle`, `JudgeDecision`, `RuntimeReceipt`, `RegressionPack`, `RolloutGate`, `SkillSnapshot`, `SessionTrace`, `ToolInvocation`, `CostRecord`, `FailureTaxonomy`.
  - **`gate-result/v1` NORMATIVE in-toto predicate body** per Blueprint B § 7.4 — the only fully spec-bound predicate at v1.
  - 10 branded primitive types: `Uuidv7`, `Sha256`, `Sha256Prefixed`, `Rfc3339`, `SemVer`, `KebabSlug`, `MicroUsd`, `StorageKey`, `OtelSpanId`, `ActorIdentity`.
  - State-machine transition maps + `canTransition` helper.
  - Composition DAG types with closed edge-kind enum (`feeds` / `gates` / `enriches`).
- **`@intentsolutions/core/schemas/v1`** — JSON Schema definitions (draft 2020-12).
  - 13 entity schemas at `schemas/v1/<entity>.schema.json`.
  - `gate-result.schema.json` with `$id = https://evals.intentsolutions.io/gate-result/v1.schema.json`.
  - `_common.schema.json` with 14 shared `$defs`.
  - `index.json` catalog.
  - Use with any JSON Schema validator (ajv, jsonschema-py, etc.).
- **`@intentsolutions/core/validators/v1`** — opt-in Zod runtime parsers.
  - Per-entity validators at `validators/v1/<entity>` for tree-shaking.
  - Branded Zod primitives mirroring the TS brands.
  - Discriminated unions for variant types.
  - `superRefine` enforcement of the Blueprint B § 7.4 `advisory_severity` conditional rule.
  - Requires `zod ^4.x` as a peer.
